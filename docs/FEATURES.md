## 회원 · 계좌

### F-01 회원가입 · 계좌 개설 — 필수

- **입력**: 닉네임, 이메일, 비밀번호, 비밀번호 확인, 계좌 이름(기본 "기본 계좌")
- **처리** (한 트랜잭션)
  1. 입력값 검사: 빈칸 없음, 이메일 형식, 비밀번호 일치
  2. 비밀번호를 해시로 바꿔 `users`에 INSERT
  3. `accounts`에 계좌 INSERT
  4. `cash_ledger`에 유형 "입금", 금액 +10,000,000 INSERT
  5. 모두 성공하면 커밋, 하나라도 실패하면 롤백
- **결과**: 가입 완료 후 마켓 화면으로 이동
- **예외**: 이메일 중복(UNIQUE 위반) → "이미 가입된 이메일입니다", 형식 오류 → 해당 칸 아래 안내
- **API**: `POST /api/signup`
- **테이블**: users, accounts, cash_ledger

### F-02 로그인 · 로그아웃 — 필수

- **입력**: 이메일, 비밀번호
- **처리**: 이메일로 사용자 조회 → 해시 비교 → 로그인 상태 저장(세션 또는 토큰)
- **결과**: 메뉴 바에 닉네임과 보유 현금 표시
- **예외**: 이메일이나 비밀번호가 틀리면 "이메일 또는 비밀번호가 맞지 않습니다" (어느 쪽이 틀렸는지 알려 주지 않음)
- **API**: `POST /api/login`, `POST /api/logout`
- **테이블**: users

## 시세 조회

### F-03 종목 목록 조회 — 필수

- **처리**
  - 종목별 최신 종가와 직전 종가를 `LAG`와 `ROW_NUMBER`로 구함
  - 전일 대비 = 오늘 종가 − 전일 종가
  - 등락률 = 전일 대비 ÷ 전일 종가 × 100, 소수 둘째 자리
  - 상승 · 하락 · 보합 종목 수 집계
- **결과**: 종목명 · 코드 · 섹터 · 현재가 · 전일 대비 · 등락률 표, 요약 카드 4개
- **예외**: 첫 거래일이라 전일 종가가 없으면 `—`
- **API**: `GET /api/stocks`
- **테이블**: stocks, sectors, prices

### F-04 종목 검색 · 섹터 필터 — 필수

- **입력**: 검색어(종목명 또는 코드), 섹터
- **처리**: 처음엔 F-03 결과를 화면에서 거르고, 종목이 많아지면 `WHERE name LIKE ? AND sector_id = ?`로 서버에서 거름
- **결과**: 조건에 맞는 종목만 표시, 없으면 "조건에 맞는 종목이 없습니다"
- **API**: `GET /api/stocks?q=&sector=`

### F-05 종목 상세 · 일별 시세 — 필수

- **처리**: 종목 정보 + 최근 거래일 시세(시가 · 고가 · 저가 · 종가)를 최신순으로 조회, 내 보유 수량 · 평균 매입가 계산
- **결과**: 현재가 · 전일 대비 · 일별 시세 표 · 내 보유 현황
- **예외**: 없는 종목 ID → 404
- **API**: `GET /api/stocks/:id`, `GET /api/stocks/:id/prices?days=`
- **테이블**: stocks, sectors, prices, orders, executions

## 주문

### F-06 시장가 매수 — 필수

- **입력**: 종목 ID, 수량
- **처리** (한 트랜잭션)
  1. 계좌 행 잠금 `SELECT … FROM accounts WHERE id = ? FOR UPDATE`
  2. 현재가 조회 (최신 종가)
  3. 현금 잔고 = `cash_ledger` 금액 합
  4. 주문 금액 = 현재가 × 수량, 잔고보다 크면 롤백
  5. `orders` INSERT (매수, 시장가, 상태 "체결")
  6. `executions` INSERT (체결가 = 현재가, 수량)
  7. `cash_ledger` INSERT (유형 "매수", 금액 −주문 금액, 체결 ID)
  8. 커밋
- **결과**: "체결 완료 · 종목 수량 금액" 메시지, 보유 현금 갱신
- **예외**: 수량 0 이하 → CHECK 위반, 잔고 부족 → "보유 현금보다 큰 금액은 주문할 수 없습니다"
- **화면 쪽 검사**: 최대 수량 = 잔고 ÷ 현재가 (내림), 초과하면 버튼 비활성화 — 화면 검사는 편의용이고, 서버 검사가 최종
- **API**: `POST /api/orders` `{ stockId, side: "BUY", qty }`
- **테이블**: accounts, prices, orders, executions, cash_ledger

### F-07 시장가 매도 — 필수

- **처리**: F-06과 같고, 4번이 "보유 수량 = 매수 체결 합 − 매도 체결 합, 매도 수량보다 작으면 롤백"으로 바뀜. 현금 원장은 +주문 금액
- **추가 계산**: 실현 손익 = (체결가 − 평균 매입가) × 매도 수량
- **예외**: "보유 수량보다 많이 팔 수 없습니다"
- **API**: `POST /api/orders` `{ stockId, side: "SELL", qty }`

## 포트폴리오 · 내역

### F-08 포트폴리오 조회 — 필수

- **처리**
  - 종목별 보유 수량 = 매수 합 − 매도 합 (`CASE` + `SUM`, `GROUP BY`, `HAVING 수량 > 0`)
  - 평균 매입가 = 이동평균법
  - 평가 금액 = 보유 수량 × 현재가, 평가 손익 = 평가 금액 − 매입 금액
  - 수익률 = 평가 손익 ÷ 매입 금액 × 100
  - 총 자산 = 현금 잔고 + 평가 금액 합, 총 수익 = 총 자산 − 10,000,000
- **결과**: 요약 박스, 보유 종목 표(평가 금액 큰 순)
- **API**: `GET /api/portfolio`
- **테이블**: orders, executions, prices, cash_ledger, stocks
- **VIEW 후보**: 계좌별 보유 종목 뷰 — F-08, F-14, F-15에서 같이 사용

### F-09 거래 내역 조회 — 필수

- **입력**: 구분 필터(전체 · 매수 · 매도 · 입금)
- **처리**: `cash_ledger`를 체결 · 주문 · 종목과 LEFT JOIN (입금은 체결이 없으므로 LEFT), 거래 후 잔고 = 시간순 누적 합 `SUM(금액) OVER (ORDER BY 일시)`
- **결과**: 최신순 표, 체결 건수 · 매수/매도 건수 · 실현 손익 · 현재 잔고 카드
- **API**: `GET /api/history?type=`
- **테이블**: cash_ledger, executions, orders, stocks

## 관리자

### F-10 관리자 시세 입력 — 필수

- **입력**: 종목, 거래일, 시가 · 고가 · 저가 · 종가
- **처리**: 검사 통과 시 `prices` INSERT
- **검사** (화면에서 미리 보여 주고, DB 제약으로 한 번 더)
  - 모든 가격 > 0 → CHECK
  - 고가 ≥ 시가 · 종가, 저가 ≤ 시가 · 종가 → CHECK
  - 같은 종목 · 거래일 없음 → 기본 키 (stock_id, trade_date)
- **예외**: 제약 위반 시 어떤 규칙에 걸렸는지 안내
- **권한**: 관리자만 (users에 관리자 여부 컬럼)
- **API**: `POST /api/admin/prices`
- **테이블**: prices

## 확장 기능

### F-11 관심 종목 — 확장

- 별 버튼으로 추가 · 삭제, 마켓 요약 카드에 개수 표시
- 기본 키 (user_id, stock_id) → 같은 종목 중복 추가 불가
- API: `POST /api/watchlist/:stockId`, `DELETE /api/watchlist/:stockId`

### F-12 가격 차트 — 확장

- `GET /api/stocks/:id/prices`로 받은 종가 배열을 Recharts 선 차트로 표시
- 상승 종목은 빨강 선, 하락 종목은 파랑 선
- 날짜는 SQL에서 `DATE_FORMAT`으로 문자열로 내려 줌

### F-13 기간 최고가 · 최저가 — 확장

- `MAX(high)`, `MIN(low)` with `WHERE trade_date >= ?`
- 차트의 최고점 · 최저점에 점과 가격 표시

### F-14 섹터별 비중 · 자산 구성 — 확장

- 섹터별 평가 금액 합 ÷ 전체 평가 금액 × 100
- 주식 대 현금 비율 막대

### F-15 수익률 랭킹 — 확장

- 계좌별 총 자산 계산 후 `RANK() OVER (ORDER BY 수익률 DESC)` — 같은 수익률은 같은 순위
- 1~3위 카드, 내 행 강조
- API: `GET /api/ranking`

### F-16 다음 거래일로 — 확장

- 관리자가 버튼을 누르면 모든 종목의 다음 거래일 시세를 생성 (F-17의 생성 로직을 한 번 실행)
- 시연할 때 원하는 순간에 가격을 움직이는 용도
- API: `POST /api/admin/next-day`

### F-17 1분마다 가격 자동 생성 — 확장

- 실제 1분 = 시뮬레이션 1거래일, Express 서버 안에서 `setInterval`
- 종목별 새 시세 계산
  1. 난수 변동 = −변동성 ~ +변동성
  2. 평균 회귀 = 0.05 × (기준가 − 전일 종가) ÷ 기준가
  3. 새 종가 = 전일 종가 × (1 + 난수 변동 + 평균 회귀), 10원 단위 반올림
  4. 최저 · 최고 한계가 밖이면 한계값으로 자름
  5. 시가는 전일 종가 근처, 고가 = max(시가, 종가) + α, 저가 = min(시가, 종가) − α
- 모든 종목을 한 트랜잭션으로 INSERT, 실패 시 전체 롤백
- 기본 키로 같은 날 중복 생성 차단
- 서버 시작 시 마지막 생성 시각을 확인해 밀린 만큼 생성
- stocks에 추가할 컬럼: `base_price`, `volatility`, `min_price`, `max_price` (CHECK: 0 < min < base < max)

### F-18 일별 자산 추이 — 선택

- 날짜별 (현금 잔고 + 그날 종가 기준 평가 금액) 계산 → 선 차트

### F-19 지정가 주문 — 선택

- 주문 시 상태 "대기"로 저장 → 새 시세가 생길 때 대기 주문 확인 → 매수는 가격 ≤ 지정가, 매도는 가격 ≥ 지정가면 체결
- 대기 중 주문 취소 기능
- 잔고 · 보유 수량을 대기 주문만큼 묶어 두는 규칙이 필요해 난이도가 높음

### F-20 타임머신 모드 — 선택

- 실제 종목의 과거 일봉 데이터를 미리 넣어 두고, "다음 거래일로"를 누를 때마다 하루씩 공개
- 데이터 출처의 이용 조건 확인 필요

## 공통 규칙

- SQL은 항상 파라미터 바인딩(`?`)
- React는 DB에 직접 접근하지 않고 API만 호출
- 화면 검사는 편의용, 최종 검사는 서버와 DB 제약
- 금액은 원 단위 정수
- 에러 응답 형식 통일: `{ "error": "사람이 읽을 수 있는 메시지" }`
